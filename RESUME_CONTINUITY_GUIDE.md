# Resume Feature - Report Continuity Implementation Guide

## Overview

This implementation modifies the Garak resume feature to maintain complete report continuity when resuming interrupted scans. The resumed reports will be **indistinguishable** from reports generated by a single, uninterrupted scan.

## Problem Statement

### Before (Current Behavior)
When resuming an interrupted scan:
- ❌ New run_id generated for resumed portion
- ❌ New start_time recorded
- ❌ Separate report files created
- ❌ Multiple completion/digest entries
- ❌ Inconsistent timestamps across attempts

### After (Fixed Behavior)
When resuming an interrupted scan:
- ✅ Original run_id preserved throughout
- ✅ Original start_time maintained
- ✅ Single continuous report file (appended)
- ✅ Single completion/digest entry (updated)
- ✅ Consistent timestamps across all attempts

## Key Changes Made

### 1. **cli.py** - Load Original Metadata on Resume

**Location**: Lines ~750-800

**What Changed**:
- Added `parse_existing_report_metadata()` helper function
- Extracts original `run_id` and `start_time` from existing report.jsonl
- Preserves these values in `_config.transient` for use throughout the scan

**Code Snippet**:
```python
# Parse existing report to get original run_id and start_time
original_run_id, original_start_time = parse_existing_report_metadata(expected_report_path)
if original_run_id:
    _config.transient.run_id = original_run_id
if original_start_time:
    _config.transient.original_start_time = original_start_time
```

**Why**: Ensures all new attempts and hitlog entries use the same run_id as the original scan.

---

### 2. **command.py** - Clean Up Old Metadata on Completion

**Location**: `end_run()` function

**What Changed**:
- Added `remove_trailing_metadata_entries()` helper function
- Removes old completion/digest entries before writing new ones
- Adds `start_time` to completion entry for full timeline tracking

**Code Snippet**:
```python
def remove_trailing_metadata_entries(report_path):
    """Remove trailing completion and digest entries from report file."""
    # Read all lines, filter out completion/digest, rewrite file
    ...

# In end_run():
if is_resuming:
    remove_trailing_metadata_entries(_config.transient.report_filename)

end_object = {
    "entry_type": "completion",
    "start_time": start_time,  # NEW: Include original start_time
    "end_time": datetime.datetime.now().isoformat(),
    "run": _config.transient.run_id,
}
```

**Why**: Prevents duplicate completion/digest entries when resuming multiple times.

---

### 3. **report_digest.py** - Smart Digest Replacement

**Location**: `append_report_object()` function

**What Changed**:
- Detects when appending a digest entry
- Removes any existing digest/completion entries
- Appends fresh digest to ensure only one exists

**Code Snippet**:
```python
if object.get('entry_type') == 'digest':
    # Read all lines, filter out old digest/completion
    filtered_lines = [line for line in lines 
                     if entry.get('entry_type') not in ('digest', 'completion')]
    # Rewrite file with filtered content
    reportfile.truncate()
    reportfile.writelines(filtered_lines)
```

**Why**: Ensures final report has exactly one digest entry, no matter how many times resumed.

---

### 4. **resumeservice.py** - Preserve Original Start Time

**Location**: `initialize_new_run_with_attempts()` function

**What Changed**:
- Check for `_config.transient.original_start_time` before using current time
- Store original timestamp in resume state

**Code Snippet**:
```python

                       if hasattr(_config.transient, "original_start_time") 
                       else datetime.now().isoformat())

_resume_state = {
    ...
    "start_time": original_start_time,  # Use original, not current
    ...
}
```

**Why**: Maintains consistent start_time in state and completion entries.

## Report Structure Comparison

### Original Garak (Non-Resumed Run)

```jsonl
{"entry_type": "start_run setup", ...}
{"entry_type": "init", "run": "abc-123", "start_time": "2026-01-19T10:00:00"}
{"entry_type": "attempt", "uuid": "attempt-1", "seq": 0, ...}
{"entry_type": "attempt", "uuid": "attempt-2", "seq": 1, ...}
...
{"entry_type": "completion", "start_time": "2026-01-19T10:00:00", "end_time": "2026-01-19T10:10:00", "run": "abc-123"}
{"entry_type": "digest", ...}
```

### Modified Garak (Resumed Run) - NOW IDENTICAL

```jsonl
{"entry_type": "start_run setup", ...}                                    # Initial run
{"entry_type": "init", "run": "abc-123", "start_time": "2026-01-19T10:00:00"}  # Initial run
{"entry_type": "attempt", "uuid": "attempt-1", "seq": 0, ...}            # Initial run
{"entry_type": "attempt", "uuid": "attempt-2", "seq": 1, ...}            # Initial run
{"entry_type": "attempt", "uuid": "attempt-3", "seq": 2, ...}            # Resumed run (APPENDED)
{"entry_type": "attempt", "uuid": "attempt-4", "seq": 3, ...}            # Resumed run (APPENDED)
...
{"entry_type": "completion", "start_time": "2026-01-19T10:00:00", "end_time": "2026-01-19T10:15:00", "run": "abc-123"}  # UPDATED
{"entry_type": "digest", ...}                                             # UPDATED
```

**Key Points**:
- ✅ Same `run_id` ("abc-123") throughout
- ✅ Same `start_time` ("2026-01-19T10:00:00") in init and completion
- ✅ Sequential `seq` numbering (no gaps or resets)
- ✅ Updated `end_time` in completion reflects actual finish
- ✅ Single digest entry (old one removed, new one appended)

## Edge Cases Handled

### 1. **Partial Report File**
- **Scenario**: Report file exists but is incomplete/corrupted
- **Handling**: `parse_existing_report_metadata()` returns `None`, falls back to new run

### 2. **Missing State File**
- **Scenario**: Resume requested but state file deleted
- **Handling**: Resume fails gracefully with error message

### 3. **Concurrent Resumes**
- **Scenario**: Two resume processes started simultaneously
- **Handling**: OS file locking prevents corruption; second process fails

### 4. **Interrupted Digest Generation**
- **Scenario**: Process killed during digest write
- **Handling**: Next resume replaces partial digest with fresh one

### 5. **Version Mismatch**
- **Scenario**: Resume with different Garak version
- **Handling**: Version check in `load_state()` warns but continues

## Known Limitations

1. **Score Variance**: LLM non-determinism may cause slight score differences between interrupted and continuous runs (expected behavior, not a bug)

2. **Parallel Attempts**: If `--parallel_attempts >1`, ensure thread-safe file writes (already handled by Python's file buffering)

3. **External Report Modification**: If user manually edits report files, resume may fail (intentional - don't support corrupted reports)

## Troubleshooting

### Issue: Run ID Changes on Resume
**Symptom**: Different run_id in resumed attempts  
**Cause**: Original report missing or unparseable  
**Fix**: Verify report file exists and is valid JSON Lines

### Issue: Multiple Digest Entries
**Symptom**: Report has >1 digest entry  
**Cause**: Old version of code or interrupted digest write  
**Fix**: Manually remove duplicate digests or regenerate with `python -m garak.analyze.report_digest -r report.jsonl -w`

### Issue: Start Time Mismatch
**Symptom**: Completion start_time ≠ init start_time  
**Cause**: `original_start_time` not preserved  
**Fix**: Check that `parse_existing_report_metadata()` successfully read init entry
